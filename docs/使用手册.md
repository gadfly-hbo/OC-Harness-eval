# OC-Harness-eval 使用手册（OptraCall 产品环境）

本手册讲操作细节；方法论与规则见 [README](../README.md)、[AGENTS](../AGENTS.md)、[测评器开发规范](测评器开发规范.md)。

## 1. 准备

### 凭证隔离 HOME

评测从 `--home` 指定的 Pi 隔离配置读取被评模型凭据，不触碰用户真实 `~/.pi` 或 `~/.optracall`：

```bash
bash scripts/setup-pi-home.sh      # 默认建在 ~/.skill-eval/pi-home
```

`~/.skill-eval/pi-home/.pi/agent/auth.json` 须含 `minimax-cn` 的 `api_key`（被评）与 `xiaomi-token-plan-cn`（评委）。`models.json`/`models-store.json` 提供模型目录。

### Node 解释器

OptraCall Host/worker 需 **Node 25+**。驱动进程本身可用 Node 22+。当前解释器不足时：

```bash
--optracall-node /path/to/node25+
```

### OptraCall checkout

提供产品源码 checkout（须已 `npm ci` 安装依赖）。环境准备只读复制它，排除 `node_modules/.git/dist/.runtime/.local`；`node_modules` 以共享只读符号链接复用同一 SDK 安装。

## 2. 预检（不产生费用）

```bash
npm run eval -- preflight \
  --model minimax-cn/MiniMax-M3.1-Flash \
  --judge-model xiaomi-token-plan-cn/mimo-v2.6-flash \
  --home ~/.skill-eval/pi-home
```

只读核验本地合并目录中的精确模型身份与原生额度。`LOCAL_MODEL_IDENTITIES_CONFIRMED` 仅表示本地可解析；远端鉴权、计费、真实调用授权仍未验证。

## 3. 对照评估（产生费用）

```bash
npm run eval -- eval \
  --suite suites/optracall-smoke.json \
  --optracall /path/to/OptraCall \
  --optracall-node /path/to/node25+ \
  --model minimax-cn/MiniMax-M3.1-Flash \
  --judge-model xiaomi-token-plan-cn/mimo-v2.6-flash \
  --home ~/.skill-eval/pi-home \
  --repeat 1 --judge-repeat 1
```

CLI 自动：准备双环境 → 走正常任务入口跑两侧 → 采集 native 会话与交付物 → 跑冻结评委轮次 → 生成 `REPORT.md` 与 `summary.json`。

规模 = `任务数 × repeat × 2` 被评会话 + `任务数 × repeat × judgeRepeat` 评委会话。开跑前确认模型与规模。

## 4. 套件

产品环境套件须声明 `optracall` 段：

```json
{
  "id": "optracall-smoke",
  "optracall": { "skillName": "data-analysis", "templateDir": "templates/optracall-data-analysis" },
  "repeat": 1, "judgeRepeat": 1,
  "tasks": [
    {
      "id": "attr-sales",
      "prompt": "…把报告保存到 060_reports/analysis.md。",
      "deliverablePath": "060_reports/analysis.md",
      "assertions": [ { "kind": "mustMatch", "pattern": "…" } ]
    }
  ]
}
```

- `templateDir` 相对套件文件，含 `010_draw`/`020_clean` 平铺文件，两侧一致上传。
- `deliverablePath` 冻结交付文件；规则与评委用其采集快照。
- 私有真值放 `.local/`，不进 skill 可读路径。

## 5. 产物与重算

运行目录 `runs/<run-id>/`：

- `cases/<variant>/<task>/<attempt>/`：`events.json`、`output.md`、`result.json`、`deliverable.md`、`optracall/`（native 会话、项目树哈希、usage）。
- `optracall-env/`：双 codeRoot/dataRoot/projectsRoot。
- `optracall-ledger.jsonl`、`budget-ledger.jsonl`、`execution-status.json`、`run-manifest.json`、`summary.json`、`REPORT.md`。

从原始产物重算（不覆盖原报告）：

```bash
npm run eval -- report --run runs/<run-id> --suite-file suites/optracall-smoke.json
```

## 6. 费用口径

三口径分开，不混报：

- **用量**：native 会话 usage（tokens），权威。
- **SDK 成本估计**：`summary.json` 的 `totalCost`。
- **保守等价上界**：`optracall-ledger.jsonl` 的 `conservativeEquivalentNanoUsd`（全输入/cache 按未缓存价）。
- **现金账单**：未知。

## 7. 判定门槛与区间

- 完整的任务等权配对断言增益须 ≥ +10pp（保守 95% Hoeffding 下界 > 0）。
- 无计分断言时，任务级纯评委胜率的保守 95% Hoeffding 下界须 > 50%。
- Hoeffding 区间以独立计分任务为统计单位；原始评委胜率的 95% Wilson 区间用于描述，不作正式判定。
- 有效评判覆盖率 ≥ 70%（且有效计分对 ≥ 4）、skill 侧超时率 ≤ 20%、全样本胜率下界 ≥ 50%。
- `--timeout <ms>` 设置被评单次超时，默认不设；`--judge-timeout <ms>` 设置评委单次超时，默认不设。

## 8. 故障速查

| 现象 | 处理 |
|---|---|
| 预检失败 | 停止，不创建运行目录 |
| `OPTRACALL_NODE_TOO_OLD` | 用 `--optracall-node` 指定 Node 25+ |
| `OPTRACALL_CREDENTIAL_MISSING` | 检查 `--home` 的 auth.json 含对应 provider |
| 单样本失败/超时 | 计入分母，继续其余样本 |
| Host 退出/环境漂移 | 停批，保全首因与未运行项 |
| 结论不足 | 如实交付 `inconclusive`，不放宽门槛 |
