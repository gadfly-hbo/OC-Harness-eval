# 测评案例与 Prompt 编写指南

三类测评（skill / sap-method / memory）的任务 prompt 与 Fixture 怎么写。示例套件在 `suites/examples/`，可直接改改用。

> **实操不必自己写套件**：你只需简要说明测评方向（测什么、业务场景、想验证什么），Agent 会按本指南草拟成规范套件（prompt＋Fixture＋断言＋矩阵），**呈现给你确认后再跑**。三个测评 skill（`/skill-eval-flow`、`/capability-eval-flow`、`/memory-eval-flow`）的 S2 都内置了这个「草拟→确认→再跑」流程。本指南供你了解规范、审阅草拟结果，或自行编写时参考。

> 通用前提：任务 prompt 两侧完全一致；交付物文件名在 prompt 里冻结（如「保存到 `060_reports/analysis.md`」）；断言先于结果冻结，检验**行为约束**而非措辞；私有真值放 `.local/`。

## 一、skill 测评

**测什么**：一个 SKILL.md 的行为契约是否改善输出。候选＝skill 包（给 skill 名即可）。

### 任务 prompt 怎么写

核心：**创造「需要该 skill 行为契约」的情境**，让装/不装产生可观测差异。

| 要点 | 说明 |
| --- | --- |
| 触发契约情境 | 任务要落在 skill 的触发范围。data-analysis 触发「分析数据/看趋势/找异常」，不触发「测算发券 ROI」 |
| 区分输出形态 | 归因分析→六段报告；单指标直答→数字+基准+口径；正式汇报→六段+方法论 |
| 冻结交付物 | 明确「保存到 060_reports/xxx.md」，两侧一致 |
| 给足输入 | 数据来源、统计期间、指标口径、样本量（skill 要求输入五项） |
| 负向题 | 用不该触发的任务测误触发（`shouldActivate:false`，diagnostic） |

**好 prompt**（归因，触发六段契约）：
```
分析 020_clean/sales.csv：2026 年 10 月相对 9 月整体销售额为什么变化？
口径与期间见 020_clean/取数说明.md。做归因分析，把完整报告保存到 060_reports/analysis.md。
```

**坏 prompt**（太泛，装不装 skill 差异小）：
```
看看这个数据。
```
→ 没有明确分析目标/形态/交付，skill 契约无从体现，区分度低。

### 断言怎么设（检验行为契约）
- 六段齐全有序：`mustMatch` 匹配「一、数据口径…二、趋势…六、行动建议」。
- 数值正确：`numeric` 匹配合成真值（如环比 +10%）。
- 红线：`mustNotMatch` 禁 AI 套话、禁无依据预测。
- 白送断言（baseline 也过的）标 diagnostic，不计增益。

完整示例：`suites/examples/skill-data-analysis.json`。

## 二、sap-method 测评

**测什么**：有已发布分析方法指导 vs 没有，分析是否更准。候选＝方法正文（Fixture）+ 任务。

### Fixture（方法正文）怎么写

四个字段，对应方法的完整契约：

| 字段 | 写什么 | 例 |
| --- | --- | --- |
| `conditions` | 适用条件/前提 | 「各渠道 visitor 与 conversion 两期数据，分母口径一致」 |
| `logic` | 方法逻辑/公式 | 「总转化率＝Σ(渠道权重×渠道转化率)，权重＝渠道visitor÷总visitor；拆解为结构效应与水平效应」 |
| `judgment` | 判定/校验规则 | 「效应之和须精确闭合到总变动（差额≤0.01pp）；先核分母口径与期间等长」 |
| `limits` | 局限/边界 | 「缺基期 visitor 无法算结构效应，保留 UNKNOWN；不得用会话数代替访客数」 |

### 任务 prompt 怎么写

核心：**创造「需要该方法」的情境**，让 Agent 主动查读已发布方法。三类任务族：

| 任务族 | purpose | 怎么写 |
| --- | --- | --- |
| 直接适用 | source-replay | 任务正好落在方法适用条件内 |
| 变体迁移 | migration | 换数据/场景，方法仍适用，测迁移 |
| 边界 | boundary | 缺关键前提（如缺基期），测 Agent 是否识别不适用、保留 UNKNOWN |

**好 prompt**（直接适用）：
```
拆解 2026 年 10 月相对 9 月整体转化率的变动归因。数据见 020_clean/conversion.csv
（各渠道 visitor 与 conversion 两期）。先查阅是否有适用的已发布分析方法，再给出拆解，
效应须闭合到总变动。把报告保存到 060_reports/analysis.md。
```

**边界 prompt**（缺基期，测边界）：
```
拆解整体转化率变动。数据见 020_clean/conversion_missing_base.csv（只有本期，缺基期 visitor）。
先查方法再判断能否拆解；不能算的部分如实标注。保存到 060_reports/analysis.md。
```

### 断言怎么设
- 方法采用：报告体现方法逻辑（结构/水平效应拆解）。
- 闭合校验：`numeric` 效应之和闭合。
- 边界：缺数据时 `mustContain`「UNKNOWN/无法计算」，`mustNotMatch` 编造数值。

完整示例：`suites/examples/sap-method-conversion.json`。

## 三、memory 测评

**测什么**：能检索并使用跨任务历史经验 vs 不能，新任务是否更好。候选＝历史经验（Fixture）+ 新任务。

### Fixture（历史经验）怎么写

每条经验是一张判断卡片：

| 字段 | 写什么 | 例 |
| --- | --- | --- |
| `caseTitle` | 经验所属事项 | 「门店缺货核查事项」 |
| `judgment.kind` | hypothesis（判断）/ strategy（方案） | hypothesis |
| `judgment.title` | 经验标题 | 「缺货归因待核」 |
| `judgment.statement` | 经验内容（带条件与 uncertainty） | 「A 门店缺货历来多是补货周期错配，非需求突增；已有权限≠已执行补货；未做因果检验」 |

经验要**带适用条件与不确定性**（不是绝对真理），才能测 Agent 是否正确参考而非盲从。可放干扰项（无关/过期经验）测抵抗。

### 任务 prompt 怎么写

核心：**新任务要创造「需要回忆相关经验」的情境**，且与历史经验相关但不相同。

| 场景 | 怎么写 |
| --- | --- |
| 相关检索 | 新任务与历史经验同类（如另一个门店缺货），应主动想起并参考 |
| 干扰抵抗 | 放入无关/过期经验，测 Agent 不被带偏 |
| 零调用 | 任务不需要历史经验，测 Agent 不乱查（零调用正常） |

**好 prompt**（相关检索）：
```
B 门店最近也出现缺货，给核查思路。先查阅是否有相关的历史判断或经验来源，
再结合 020_clean/取数说明.md 分析。注意区分历史判断与已证实事实。
把结论保存到 060_reports/analysis.md。
```

**坏 prompt**（直接给答案，无需记忆）：
```
B 门店缺货是因为补货错配，写个报告。
```
→ 结论已喂给 Agent，记不记忆无差异，区分度低。

### 断言怎么设
- 主动检索：取证 `read_case_sources` find/read 成功（consulted）。
- 正确参考：报告引用历史判断且标注「未做因果检验/待核」。
- 区分判断与事实：`mustNotMatch` 把历史判断当已证实结论。
- 干扰抵抗：不被无关经验带偏。

完整示例：`suites/examples/memory-stockout.json`。

## 四、三类对比速查

| | skill | sap-method | memory |
| --- | --- | --- | --- |
| 候选 | skill 包（给名） | 方法正文 Fixture | 历史经验 Fixture |
| 唯一变量 | 装/不装 skill | 能/不能查读方法 | 能/不能检索经验 |
| prompt 关键 | 触发 skill 契约情境 | 需要该方法的情境 | 需要回忆相关经验的新任务 |
| 交付物 | 报告（六段/直答） | 分析报告（方法应用） | 核查思路（参考经验） |
| 核心断言 | 行为契约（六段/数值/红线） | 方法采用+闭合+边界 | 主动检索+正确参考+抗干扰 |

## 五、通用避坑

- **别喂答案**：prompt 里别把结论直接给出，否则装/不装无差异。
- **别太泛**：「看看数据」没有可观测契约差异；要明确目标/形态/交付。
- **断言测行为非措辞**：测「六段齐全」「效应闭合」，不测「是否包含『建议』二字」。
- **负向/边界题单列**：误触发、不适用场景标 diagnostic，不计增益。
- **真值合成可公开**：合成数据真值可放套件；真实业务真值放 `.local/`。
- **先跑冒烟**：新套件先用 repeat=1 冒烟验链路，再扩独立任务与重复做正式测评。
